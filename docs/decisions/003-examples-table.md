# ADR-003 振る舞いを例の表で書く

状態：採用（2026-09-30）

## 背景

Issue の要求を文章で書くと，条件の組み合わせ，境界，例外が読み取りにくい．agent も人も，どこまでが範囲かを
読み違える．

## 判断

- Issue の「振る舞いの例」は，`状況`，`入力・操作`，`期待する結果` の 3 列の表で書く．1 行に 1 つの例を置く．
- 境界（上限ちょうど，上限を超える）と例外（権限がない）も行として書く．
- PR では，各行をどの test で確かめたかを「確かめたこと」に書く．
- 振る舞いが変わらない作業では「なし（振る舞いは変えない）」と書く．

## 理由

- 行を足すだけで境界と例外を増やせ，抜けが目で見て分かる．
- 1 行がそのまま test の case になるので，Issue から test への対応を追いやすい．
- Given-When-Then の文章より短く，GitHub の画面で一覧できる．

## 他の案

- Given-When-Then の文章：1 規則ごとに 3 行が必要で，規則が増えると縦に長くなる．
- 受け入れ条件の checklist だけ：境界と例外が書かれないことが多い．

## 結果

複数の段階を経る振る舞い（手順が長い操作）は，1 行に収まらないことがある．その場合は「入力・操作」に要点だけを書き，
詳細を「手がかり」に書く．
