# レビューの観点

## 目的

PR の差分を，対応する Issue の契約と照らして検査する．実装した agent 自身の思い込みを持ち込まないため，
可能な場合は実装とは別の context（Claude Code の `reviewer` subagent，Codex の別 session または `/review`）で行う．

## 重要度

| 重要度 | 意味                                                              | 扱い                 |
| ------ | ----------------------------------------------------------------- | -------------------- |
| P0     | data の破壊，security 事故，secret の漏洩，main が壊れる          | 必ず修正する         |
| P1     | 要求振る舞いまたは受け入れ条件を満たさない，回帰，テストの欠落    | 必ず修正する         |
| P2     | 保守性，命名，重複，軽微な edge case                              | 修正するか理由を書く |
| P3     | 好みの範囲の提案                                                  | 任意                 |

## 観点

1. **契約との一致**：Issue の要求振る舞いと受け入れ条件を全て満たしている．範囲外の変更を含まない．
2. **正しさ**：境界値，null や空の入力，error の経路，並行実行，時刻と timezone．
3. **security**：入力検証，認可，secret と個人情報の扱い，依存 package の追加理由．
4. **テスト**：各振る舞いに最低十分な層のテストがある．テストが実装の詳細ではなく振る舞いを検査している．
5. **既存への影響**：公開 API，設定，data の互換性，削除したコードの呼び出し元．
6. **PR 本文**：`docs/architecture/issue-pr-authoring.md` の review の観点を満たす．特に確認結果が現在の head の実績だけである．

## 指摘の書き方

指摘は 1 件ごとに次の形式で書く．根拠のない指摘や，差分と関係ない指摘はしない．

```text
[P1] src/invitations/resend.ts:42
問題：期限切れでない招待も再送できる．
根拠：Issue の要求振る舞い「期限切れの招待を再送する」と受け入れ条件 2 に反する．
提案：status が expired でない場合は 409 を返す．
```

指摘がない場合は「P0/P1 なし」と明記し，確認した観点を列挙する．
